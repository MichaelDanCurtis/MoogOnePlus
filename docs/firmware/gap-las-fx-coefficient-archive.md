# `tables/coefsEnvir` — the 5.4 MB SuperCollider archive, decoded

Scope: `usr/share/las-fx/tables/` in the decrypted v1.8.2 root filesystem, compared
against v1.5.0. Everything below was obtained by reading files on local disk. **The
instrument was not touched.** No Moog binary was executed. Proposed on-instrument
checks are confined to §16, are read-only, and are for a human to run.

Every claim carries a grade: **[READ]** = read directly out of a named file at a named
offset or line; **[INFERRED]** = reasoning from stated evidence; **[UNKNOWN]** = not
determined.

---

## 0. Headline

The archive decodes completely. It is **not** a filter design in any proprietary sense
— it is a memoised evaluation of four textbook biquad formulas over a linear frequency
grid, and 93.5% of its 576,000 stored doubles are bit-for-bit reproducible from the
generator script sitting next to it. **[READ]**

Two facts fall out of the decode that no prior report has:

1. The shipped archive contains **65** coefficient arrays, but
   `tables/gen_tables.scd` generates **70**. The whole `bpf_q20_*` bank (five arrays,
   0.20-octave bandpass) is declared and generated by the script and is **absent from
   the archive**. **[READ]**
2. The shipped `hpf_*` bank was generated over the frequency range **20 Hz → 16 kHz**,
   but `gen_tables.scd:377` specifies **1 Hz → 16 kHz**. The discrepancy is 1.2e-3
   relative — four orders of magnitude above the 1e-16 rounding noise everywhere else
   — and the shipped `hpf_b1_arr`/`hpf_b2_arr` are **byte-identical** to
   `lpf_b1_arr`/`lpf_b2_arr`, which they could not be if the two banks used different
   frequency maps. **[READ]**

So: **`gen_tables.scd` is not the program that produced the shipped `coefsEnvir`.**
It is a *later* revision of it. The file on the device is stale build output. **[INFERRED]**

Everything else confirms `las-fx.md`'s "dead" verdict and hardens it from three
directions the prior report did not use: the only two effect classes that ever called a
`*Table` filter have those calls **commented out** in source; the loader
`load_tables.scd` is not merely commented out of the boot path but is **stale against
the two scripts that still call it** (it needs a server named `\server_main` that only
`init_sc_1.scd` registers); and the plain `Index` UGen the all-pass and bandpass
wrappers depend on appears in **zero** of the 104 compiled synthdefs. **[READ]**

## 2. The container format, reconstructed

`sclang` is stripped ARM ELF **[READ]** (`file`: `ELF 32-bit LSB executable, ARM,
EABI5 … stripped`), and the `!SCa` magic is not present in it as a string literal
**[READ]** (byte search for `!SCa` and for the `MOVW #0x5321` immediate over `.text`
both returned nothing), so the format below was reconstructed from the data. The
reconstruction consumes the file to **exactly** its last byte with zero trailing
bytes, produces a well-formed 66-entry dictionary whose keys match the generator
script's variable names one-for-one, and whose values reproduce the generator's
formulas — so it is right. **[INFERRED]** — exhaustive round-trip.

`Object.sc` in the rootfs confirms the two entry points are primitives:
`writeBinaryArchive { _WriteArchive }` at `SuperCollider/SCClassLibrary/Common/Core/Object.sc:931`
and `*readBinaryArchive { _ReadArchive }` at `:935`. **[READ]**

### 2.1 Layout

```
offset  size  content
0x0000  4     magic            "!SCa"
0x0004  4     version          uint32 BE  = 2
0x0008  4     object count N   uint32 BE  = 68
0x000c  ...   OBJECT TABLE     N entries, each:
                                 uint8   len of class name
                                 char[len] class name
                                 uint32 BE size   (slots, or bytes for String)
0x02bb  ...   DATA SECTION     N object bodies, in table order
```

The object table is a **prologue**: every object's class and size is declared up front,
then the bodies follow in the same order. Object indices are 0-based; object 0 is the
archive root. **[READ]** — header bytes at 0x0000–0x02ba; body boundaries verified by
the exact-fit parse.

### 2.2 Slot encoding (data section)

A non-`String` object body is `size` slots, each a 1-byte tag plus payload:

| tag | ASCII | payload | meaning |
|---|---|---|---|
| `0x4e` | `N` | — | `nil` |
| `0x54` | `T` | — | `true` |
| `0x46` | `F` | — | `false` |
| `0x69` | `i` | int32 BE | Integer |
| `0x66` | `f` | **float64 BE** | Float |
| `0x73` | `s` | uint8 len + chars | Symbol |
| `0x6f` | `o` | uint32 BE | reference to object #n |
| `0x63` | `c` | uint8 | Char |

**[READ]** — `N`/`T`/`F`/`i`/`s`/`o` observed at 0x02bb–0x08ad; `f` observed from
0x08ae onward (e.g. `66 bf3ddde0d8d9203d` at 0x08ae). `c` was inferred by symmetry and
never occurs in this file. **[INFERRED]** for `c` only.

A `String` body is `size` raw bytes with no per-character tags. **[READ]** — object 21,
0x17e92e–0x17e965, 56 bytes of ASCII.

### 2.3 The root object

Object 0 is class `Environment`, 5 slots, at 0x02bb–0x02c7 (13 bytes): **[READ]**

```
6f 00000001   -> object #1        (the hash-table Array)
69 00000042   -> Integer 66       (number of key/value pairs)
4e            -> nil              (proto)
4e            -> nil              (parent)
46            -> false            (know)
```

Those five slots are exactly `Set`'s `array, size` plus `IdentityDictionary`'s
`proto, parent, know`, in declaration order. **[INFERRED]** — from the SC class
hierarchy `Environment : IdentityDictionary : Dictionary : Set`, corroborated by the
values being (Array, 66, nil, nil, false).

Note for the record: `load_tables.scd:3` reads it as
`IdentityDictionary.readBinaryArchive(...)`, but the archived class is
**`Environment`**, a subclass. **[READ]** — class name at 0x000d is `Environment`.
`readBinaryArchive` is a primitive returning the archived class regardless of the
receiver, so this is harmless, but existing docs that call the file "a binary
`IdentityDictionary` archive" are describing the call site, not the file. **[INFERRED]**

### 2.4 The dictionary

Object 1 is `Array`, 256 slots, 0x02c8–0x08ad. It is the open-addressed hash table:
128 key/value pairs, of which **66** are occupied and 62 are `nil`/`nil`. **[READ]**
Keys are Symbols, values are object references (or, for `path`, a reference to the
String). Slot order is hash order, not declaration order — the first occupied pair is
`bpf_q50_a2_arr → object #2`. **[READ]**

### 2.5 Reference decoder

Verified against this file; consumes it to EOF with zero remainder.

```python
import struct
def read_sca(path):
    d = open(path, 'rb').read()
    assert d[:4] == b'!SCa'
    ver, n = struct.unpack_from(">II", d, 4)
    off = 12; hdrs = []
    for _ in range(n):
        ln = d[off]; name = d[off+1:off+1+ln].decode()
        sz = struct.unpack_from(">I", d, off+1+ln)[0]
        hdrs.append((name, sz)); off += 1 + ln + 4
    pos = off
    def slot():
        nonlocal pos
        t = chr(d[pos]); pos += 1
        if t == 'N': return None
        if t == 'T': return True
        if t == 'F': return False
        if t == 'i': v = struct.unpack_from(">i", d, pos)[0]; pos += 4; return v
        if t == 'f': v = struct.unpack_from(">d", d, pos)[0]; pos += 8; return v
        if t == 's': l = d[pos]; pos += 1; v = d[pos:pos+l].decode(); pos += l; return ('sym', v)
        if t == 'o': v = struct.unpack_from(">I", d, pos)[0]; pos += 4; return ('obj', v)
        if t == 'c': v = d[pos]; pos += 1; return ('char', v)
        raise ValueError("tag %r at 0x%x" % (t, pos-1))
    objs = []
    for name, sz in hdrs:
        if name == 'String':
            objs.append(d[pos:pos+sz].decode()); pos += sz
        else:
            objs.append([slot() for _ in range(sz)])
    assert pos == len(d), (pos, len(d))
    tbl = objs[1]
    env = {}
    for i in range(0, len(tbl), 2):
        if tbl[i] is not None:
            k = tbl[i][1]; v = tbl[i+1]
            env[k] = objs[v[1]] if isinstance(v, tuple) and v[0] == 'obj' else v
    return env
```

## 5. Finding 2 — the high-pass bank uses the wrong frequency range

`gen_tables.scd:377` builds the HPF frequency map as
`a = ~linearInterp.value( [1, 16000], [9600]);` — starting at **1 Hz**. **[READ]**
The LPF map at `:289` and the BPF map at `:218` both start at **20 Hz**. **[READ]**

Recomputing the HPF bank from the script's own formulas:

| candidate frequency map | slots matching the shipped data | worst relative error |
|---|---|---|
| 1 Hz → 16 kHz (as `gen_tables.scd:377` says) | **0 / 48000** | 1.244e-03 |
| 20 Hz → 16 kHz | 42,972 / 48000 bit-exact, rest within 1 ULP–few ULP | 5.5e-16 |

**[READ]** — recomputation against the decoded arrays.

Two independent corroborations, both **[READ]**:

* `hpf_b1_arr` is **element-wise identical** to `lpf_b1_arr`, and `hpf_b2_arr` to
  `lpf_b2_arr`. The `b1`/`b2` formulas are the same in `~genLPcoef` and `~genHPcoef`,
  so identical output is possible only if both banks were driven by the same
  frequency array.
* `hpf_a0_arr[0] = 0.9986910045533587`. With `k = 1 + cos(w0)` and
  `b0rz = 1/(1 + sin(w0)/2)`, `a0 = k·0.5·b0rz` tends to `b0rz` at low frequency;
  `b0rz(20 Hz) = 0.998691…`, `b0rz(1 Hz) = 0.999935…`. The stored value is the 20 Hz
  one.

**Conclusion**: the shipped `hpf` bank predates the change of `~genHPcoef`'s lower
bound from 20 Hz to 1 Hz. Combined with §4, the shipped `coefsEnvir` is output of an
**earlier revision** of `gen_tables.scd` than the one that ships beside it. **[INFERRED]**

A third, softer corroboration of drift: `gen_tables.scd:440–441` carry two commented
lines pointing at `…/efx-dev/filters/tables/coefsEnvir`, while the live write at `:443`
targets `…/las-fx/lookup filters/tables/coefsEnvir`. The `~path` value *stored inside
the archive* is the **old** `efx-dev` path. **[READ]** So the archive was written before
the project was reorganised from `efx-dev/filters/` to `las-fx/lookup filters/`, and
the script was edited afterwards. **[INFERRED]**

## 6. The filter designs, exactly as shipped

### 6.1 The biquad convention

The consumers pass the five arrays straight into SuperCollider's `SOS` UGen
(`APFTable.sc:32`, `BPFTable.sc:32`, `LPFTable.sc:24`, `HPFTable.sc:24`) **[READ]**,
whose difference equation is

```
y[n] = a0·x[n] + a1·x[n-1] + a2·x[n-2] + b1·y[n-1] + b2·y[n-2]
```

i.e. the feedback coefficients are **added**, so the transfer function is

```
        a0 + a1·z⁻¹ + a2·z⁻²
H(z) = ──────────────────────
        1 − b1·z⁻¹ − b2·z⁻²
```

**[INFERRED]** — from the SC `SOS` convention; independently confirmed below by
evaluating `H(e^{jω})` on the stored coefficients and getting exactly the intended
responses (unity all-pass modulus, unity DC gain for the LPF, unity Nyquist gain for
the HPF, unity peak for the BPFs).

`SOS` is present in the shipped plugin set (`usr/lib/SuperCollider/plugins/FilterUGens.so`),
as are `Lag`, `LPF`, `HPF`, `BPF`, `BAllPass`. **[READ]** — NUL-delimited name search.

### 6.2 All-pass banks — `ap_bw{100,500,1000,2000,3000}`

`gen_tables.scd:123–166`. **[READ]**

```
c  = (tan(π·BW/fs) − 1) / (tan(π·BW/fs) + 1)      // BW in Hz, constant per bank
d  = −cos(2π·fc/fs)                                // fc = table index → Hz, §7

a0 = −c        a1 = d·(1 − c)        a2 = 1
b1 = −d·(1 − c)                      b2 = c
```

Substituting into §6.1 gives numerator `[−c, d(1−c), 1]` over denominator
`[1, d(1−c), −c]` — the numerator is the exact reversal of the denominator, which is
the defining property of a discrete all-pass. **[INFERRED]** This is the standard
second-order all-pass section used to build tunable notch/peak filters and phasers
(Zölzer/DAFX form, parameterised by a bandwidth constant `c` and a centre-frequency
constant `d`). **[INFERRED]** — recognition of a textbook form; the formulas themselves
are **[READ]**.

Verified on the stored data: `|H(e^{jω})| = 1.000000000` at 50 Hz, 500 Hz, 4.85 kHz,

## 7. Index → frequency mapping

The consumers index the buffers with `Index.ar(bufnum, freq)` / `IndexL.ar(bufnum, freq)`
**[READ]** (`APFTable.sc:26–30`, `BPFTable.sc:26–30`, `LPFTable.sc:18–22`,
`HPFTable.sc:18–22`). The `freq` argument is therefore a **buffer frame index**, not
hertz. **[INFERRED]** — from the `Index` UGen's semantics; corroborated by the actual
call sites, which pass 380, 7785, 100 and 16000 (`Flanger.sc:55–57`) and `table_index`
initialised to 0 (`Phaser6Stage.sc:28, 58`). **[READ]**

`~linearInterp` (`gen_tables.scd:10–21`) with `arrValues = [lo, hi]`, `arrSteps = [9600]`
produces `res[j] = lo + (j/9601)·(hi − lo)` for `j = 0…9600`, then appends `hi`
(9602 entries). The generator loops `i = 0…9599`. **[READ]** So:

| family | index → Hz | f(0) | step (Hz) | f(9599) |
|---|---|---|---|---|
| `ap_bw*` | `77 + i·9165/9601` | 77.000 | 0.954588 | 9240.091 |
| `bpf_*`, `lpf`, `hpf` | `20 + i·15980/9601` | 20.000 | 1.664410 | 15996.671 |

**[READ]** — endpoints recovered *from the shipped data* by inverting the coefficient
formulas (all-pass: `fc = (fs/2π)·acos(−a1/(1−c))`; biquad: recover `alpha` from `b2`,
then `cos w0` from `b1`), independently of the generator script. All eight banks give
identical endpoints within their family.

**The maps are linear in Hz, not exponential.** A 1 Hz resolution filter sweep is
therefore coarse at the bottom of the range (the all-pass table's first step is
0.95 Hz at 77 Hz — about 21 cents) and fine at the top (0.95 Hz at 9.2 kHz — 0.18
cents). **[INFERRED]** The vestigial comment `//fc = i * 2.5;` at `gen_tables.scd:134`
and `:294` shows an even coarser earlier map. **[READ]**

Inverse, for anyone who wants Hz: `i_ap = round((f − 77)·9601/9165)`,
`i_bp = round((f − 20)·9601/15980)`. Values outside 0…9599 are clipped by `Index`.
**[INFERRED]**

## 11. What reviving it would cost

If someone uncommented `init_sc_1.scd:28`, `load_tables.scd:23–26` would load **four**
banks only — `ap_bw500_`, `ap_bw1000_`, `ap_bw2000_`, `ap_bw3000_` — 20 buffers.
`ap_bw100_` and every BP/LP/HP load sits inside a `/* … */` block at `:27–42`. **[READ]**
So 45 of the 65 arrays would remain unreferenced even in the intended configuration.
**[INFERRED]**

And if someone did uncomment that block, it would **break on line 30**:
`~loadTable.value( \bpf_q20_ );` **[READ]** asks for `bpf_q20_a0_arr`, which §4 shows
is not in the archive. `~coefs[\bpf_q20_a0_arr]` returns `nil`, and
`Buffer.loadCollection` immediately does `collection.as(FloatArray)` on it
(`Buffer.sc:194`) **[READ]**. So `load_tables.scd` is itself written against the
**newer** `gen_tables.scd` — the one with the `q20` bank — and is incompatible with
the archive shipped beside it. That is a third independent witness to the drift in §4
and §5. **[INFERRED]**

`Buffer.loadCollection` on a local server does not send the data over OSC: it coerces
the collection with `collection.as(FloatArray)`, writes a temp soundfile under
`PathName.tmp`, and `allocRead`s it, deleting the temp file in the completion action
(`SCClassLibrary/Control/Buffer.sc:186–212`). **[READ]** `PathName.tmp` is
`Platform.defaultTempDir` (`PathName.sc:33`). **[READ]**

Consequences, all **[INFERRED]** from that source:

* **The float64 precision in the archive is discarded at load.** `FloatArray` is
  32-bit. So the doubles that make the file 5.4 MB buy nothing at runtime; a float32
  store would have been half the size and bit-identical after loading.
* Twenty temp soundfiles of 9600 float32 frames (~38 KB each, ~768 KB total) would be
  written and deleted under the temp dir during boot, on a device whose boot path is
  already timing-sensitive.
* Twenty scsynth buffers at 9600 frames — trivial against the default buffer count.
* Each `*Table.ar` instance adds five `Index`/`IndexL` + five `Lag` UGens per filter
  section at audio rate. `Flanger.sc:54`'s own comment estimates the commented-out
  three-filter block at "~5% cpu increase". **[READ]**

This is out of scope to attempt, and §16 proposes nothing that would do it.

## 15. What this does **not** change

* The `-z 128` block size stands. `init_sc_1.scd:9–10` sets
  `options.blockSize = 128` and `options.hardwareBufferSize = 128`. **[READ]**
  (`init.scd:14` and `init_sc_2.scd` say 256, and both are dead paths.)
* Nothing here touches the OSC namespace, the modulation matrix, MIDI routing, or the
  XMOS boundary. `coefsEnvir` has no OSC address, no preset field, and no consumer
  outside sclang. **[READ]** — `grep -rl coefsEnvir` over the whole rootfs returns
  `load_tables.scd` and `gen_tables.scd` only; no binary matches. That negative had
  never been stated as a *checked* negative before.

## 16. Validation plan (read-only; for a human to run on the instrument)

None of these write anything. Do not run any Moog binary. Each is a single read.

1. Confirm the on-device file is the same one that was decoded:
   ```
   md5sum /usr/share/las-fx/tables/coefsEnvir
   ```
   Expect `f36f88c9444d9c5bb38187d86d698185`.

2. Confirm the `bpf_q20` absence on the device itself (§4), without a parser. Key
   symbols are stored as plain ASCII in the hash table at 0x02c8–0x08ad, so:
   ```
   strings -a /usr/share/las-fx/tables/coefsEnvir | grep -E '^(ap_|bpf_|lpf_|hpf_)' | sort
   strings -a /usr/share/las-fx/tables/coefsEnvir | grep -c 'bpf_q20_'
   strings -a /usr/share/las-fx/tables/coefsEnvir | grep -c 'bpf_q200_'
   ```
   Expect **65** key lines, `0` for `bpf_q20_`, and `5` for `bpf_q200_`.
   **Use the trailing underscore.** Without it, `bpf_q20` also matches `bpf_q200`
   and the test silently passes when it should fail — `grep -ac bpf_q20 coefsEnvir`
   on the decrypted copy returns 5, not 0. **[READ]** — verified on the local copy.

   Incidental confirmation of §2.2 while you are there: each key printed by `strings`
   ends in a stray `o` (e.g. `bpf_q50_a2_arro`). That `o` is the `0x6f`
   object-reference tag of the *value* slot that immediately follows the key symbol.
   **[READ]**

3. Confirm the loader really is commented out on the running firmware:
   ```
   sed -n '25,32p' /usr/share/las-fx/init_sc_1.scd
   ```

4. Confirm no coefficient buffers exist at runtime — from the host, an OSC read only:
   send `/b_query 0` … `/b_query 24` to scsynth on 127.0.0.1:57110 and check that no
   buffer reports `numFrames == 9600`. **This is a query, not a write**; if there is
   any doubt about the safety of touching scsynth's OSC port, skip it — the file-side
   evidence in §10 is already conclusive.

5. Settle §10.4 — whether the plain `Index` UGen is registered:
   ```
   grep -c 'Index' /usr/lib/SuperCollider/plugins/OscUGens.so
   ```
   is *not* sufficient. The clean read-only test is to ask a running sclang
   `Index.class.name` — but that requires an interactive sclang, which is not
   read-only in spirit. Preferred: on a workstation copy of `OscUGens.so`, disassemble
   the `load()` constructor and read the `DefineSimpleUnit` argument list. No device
   access needed.

6. Confirm the v1.5.0 identity claim from the owner's own instrument, if a 1.5.0 unit
   is still reachable:
   ```
   md5sum /usr/share/las-fx/tables/gen_tables.scd
   ```
   Expect `c752d5955ec0958200cafd5e535718b6`.

## 17. Unexplored

* **The `.so` UGen plugin set.** 200-plus plugins under
  `usr/lib/SuperCollider/plugins/`; only the handful named in §6.1 and §10.4 were
  checked for symbol presence. Whether the shipped scsynth registers `Index` is
  **[UNKNOWN]** (§10.4).
* **`Crossover.sc`.** Present in `LookupFilters/` but uses no table at all — it is a
  plain recursive `LPF` band-splitter (`Crossover.sc:2–14`) **[READ]**. Its call sites
  were not searched.
* **The bitcrusher `IndexL` buffer.** Four compiled synthdefs index *some* buffer; which
  one, and where it is allocated, was not traced.
* **`~linearInterp`'s off-by-one.** It emits 9602 values for a 9600-point table and the
  generators use the first 9600, so the nominal upper endpoints (9242 Hz, 16000 Hz) are
  never actually reached — the tables stop at 9240.09 Hz and 15996.67 Hz (§7). Whether
  that matters to anything is moot while the tables are dead.
* **Whether an older `gen_tables.scd` survives anywhere.** §4 and §5 prove one existed;
  no copy was found in either rootfs or in `captures/arch-harvest/` **[READ]**
  (`find` for `*coef*`, `*gen_tables*`, `*load_tables*` in `arch-harvest` returned
  nothing).
* **`sclang`'s archiver primitives.** `_WriteArchive`/`_ReadArchive` were located as
  strings but not disassembled; the format spec in §2 is reconstructed from data, not
  read out of code (§2, opening paragraph).
